# CIDR 合并优化基准

测试日期：2026-10-29。基线：`b14976e2`（先执行 `git pull` 后的版本）。

环境：Node.js v22.20.0，Linux x86_64，Intel Xeon Gold 6133 @ 2.50 GHz。

真实数据共 1,033 个文件、465,277 条 IPv4、0 条 IPv6；所有文件各自都已按规范化后的 IPv4 打包键升序排列。

## 方法

先预热 3 遍，再交替执行基线和优化版，各测 5 轮，取每轮平均耗时的中位数。每轮至少 300 ms 且至少 5 次完整工作负载。文件读取、数据准备与输出一致性检查不计时；每个场景都逐项确认两个版本输出完全一致。默认 `sort=true`，其他模式在场景名中标明。

耗时单位为 ms；耗时减少 = 1 - 优化后 / 优化前。共享环境中的小幅波动不能作为稳定收益的证据。

## 优化前后

| 场景 | 输入条数 | 优化前 ms | 优化后 ms | 耗时减少 |
| --- | ---: | ---: | ---: | ---: |
| CN.txt | 5,665 | 1.60 | 1.30 | 19.1% |
| non-china (all countries except CN) | 235,123 | 50.77 | 49.15 | 3.2% |
| cncity/*.txt (375 files) | 96,776 | 27.24 | 23.44 | 14.0% |
| every data/**/*.txt separately (1033 files) | 465,277 | 137.06 | 112.71 | 17.8% |
| all data/**/*.txt concatenated | 465,277 | 103.45 | 95.41 | 7.8% |
| IPv4 ascending | 26,188 | 8.62 | 7.55 | 12.4% |
| IPv4 descending | 26,188 | 8.19 | 8.12 | 0.9% |
| IPv4 shuffled (seed 42) | 26,188 | 11.11 | 10.64 | 4.2% |
| mixed synthetic sort=false | 20,000 | 50.39 | 49.44 | 1.9% |

IPv4 顺序用例来自真实数据合并后的 26,188 条 CIDR；乱序使用固定种子 42。IPv6 `/128` 合成用例为 10,000 个不相邻的单地址；混合用例包含 10,000 条 IPv4 和 10,000 条 IPv6。纯 IPv6 场景在最终减少单地址族排序辅助数组分配后单独重测，结果如下；未改动 IPv6 解析、bitLength 或区间算法。

| 场景 | 输入条数 | 优化前 ms | 优化后 ms | 耗时减少 |
| --- | ---: | ---: | ---: | ---: |
| IPv6 synthetic 10000 /128 | 10,000 | 45.72 | 45.40 | 0.7% |
| IPv6 synthetic 10000 /128 sort=false | 10,000 | 46.84 | 45.48 | 2.9% |
| IPv6 synthetic 10000 /64 | 10,000 | 47.45 | 45.14 | 4.9% |

首轮纯 IPv6 `/128 sort=true` 为 46.62 → 49.17 ms，复测仍约慢 5%；进一步仅在需要混合地址族排序时才分配 starts 数组后，得到上表最终结果。小幅收益仍需结合运行波动看待。

## 分步测量

以下每步只与前一步比较，使用全部 1,033 个文件分别合并的工作负载。跨行绝对耗时受运行时状态影响，不应直接相减或累加。

| 改动 | 前一步 ms | 本步 ms | 耗时减少 |
| --- | ---: | ---: | ---: |
| 用除法与减法替换 mergeV4 的 `% 64` | 142.62 | 144.55 | -1.4% |
| 再使用 int32 解析和位移掩码 | 144.06 | 140.12 | 2.7% |
| 再检测有序输入并跳过排序 | 139.71 | 120.98 | 13.4% |

分步测量中，主要收益来自跳过排序；不能据此确认 `% 64` 经过 fmod，也不能宣称替换它有稳定性能收益。`sort=false` 或只有单一地址族时停止维护跨地址族排序所需的起始地址数组；这个改动不影响纯 IPv4 工作负载。

## IPv6 试验与范围

额外试验了 BigInt 分段移位配合 `Math.clz32`，替代 `bitLength` 的二进制字符串分配：

| 场景 | 原 bitLength ms | 分段版 ms | 耗时减少 |
| --- | ---: | ---: | ---: |
| IPv6 synthetic 10000 /128 | 45.96 | 46.57 | -1.3% |
| IPv6 synthetic 10000 /128 sort=false | 45.86 | 45.00 | 1.9% |
| IPv6 synthetic 10000 /64 | 46.38 | 44.31 | 4.5% |

该试验以已优化的 IPv4 版本为基线，其他代码不变。`/64` 用例在不同 `/48` 下各取一个 `/64`，防止相邻网段合并掩盖输出成本。

鉴于真实输入没有 IPv6，且试验收益有限、`/128` 无稳定改善，最终没有引入该 bitLength 改动，也没有重写 IPv6 解析、存储或排序。百万级基数排序也未引入。

## 复现

在仓库根目录执行：

```sh
git show b14976e2:src/lib/cidr.js > /tmp/iplist-cidr-before.js
npm test
node bench/merge.bench.js --baseline /tmp/iplist-cidr-before.js --extended --json /tmp/iplist-cidr-bench.json
```

只测真实数据可去掉 `--extended`；`--filter separately` 只测逐文件工作负载。`--candidate /path/to/cidr.js` 可指定待测实现，支持逐步对比。不传 `--baseline` 时保留原单版本基准方式。

新增回归用例覆盖 IPv4 全部 33 种前缀、无符号边界、重复键、规范化后顺序变化及 IPv6 穿插时的顺序检测；现有真实数据与随机 oracle 测试继续保留。

验证：`npm test` 通过；`node test/cidr.test.js` 明确输出 12 项测试全部通过；`git diff --check` 通过。
